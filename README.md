# Telco Counterfactual Twin

A contract-first portfolio project for evaluating synthetic telecom changes in a deterministic twin before an evidence-only approval decision. It does not connect to an operator network, use customer data, or expose any execution surface.

## Bootstrap status

Todo 1 establishes specifications, strict Python 3.12 and TypeScript workspaces, CI, and a redacted deployment-authority preflight. No simulator, API, MCP server, or product UI is implemented in this commit.

The preflight intentionally distinguishes two valid outcomes:

- `deployment-ready`: every required provider permission has direct evidence and every temporary resource was removed or restored.
- `deployment-blocked`: at least one provider authority is unavailable or unproven. This exits zero because blocked is truthful, not a test failure.

Invalid or credential-bearing reports exit three. The initial environment has no GCP, Cloudflare, or Neon authority, so a ready claim would be false.

## Verify the contract boundary

```bash
make verify
```

Run a preflight after the bootstrap commit is pushed and its WIF workflow is dispatched:

```bash
bootstrap_sha="$(git rev-parse HEAD)"
uv run --project backend python scripts/deployment_preflight.py \
  --bootstrap-sha "$bootstrap_sha" \
  --report \
  --out artifacts/deployment/preflight.json
uv run --project backend python scripts/deployment_preflight.py \
  --validate artifacts/deployment/preflight.json
```

The report contains status, booleans, blocker names, and SHA-256 receipts only. It never contains credential values.

## Source and claim boundaries

- All topology, telemetry, alarms, users, and scenarios will be synthetic.
- Benchmark values may appear only when generated by the pinned repository commit and command recorded in an artifact.
- Approval is an evidence state; it is not authorization to mutate a real or simulated network.
- Public deployment links will be added only after live deployment and end-to-end evidence exist.

## 한국어 요약
